# Field selection

How a battle's initial field is chosen. Implemented by `FieldApi.choose` (selections) and `EnvironmentResolver` (environment), with Minecraft state captured by `EnvironmentProbe`.

## Precedence

```text
RCT configured field (explicit / trainer / arena selection)
        >
submerged / underwater
        >
configured generated structure
        >
biome mapping (biome, biome tag, dimension, depth rows)
        >
fallback (rejuvenation:indoor)
```

1. **Explicit or RCT-configured field.** A field selected before the battle starts always wins: `FieldApi.select(..., EXPLICIT)`, the Kanto league map in `rejuvenation/trainers/*.json` (selected by `TrainerFieldBridge` at TRAINER priority), or an ARENA selection. Underwater status, structures and biomes are not consulted for such a battle.
2. **Underwater.** The battle is submerged when the anchor (the wild Pokémon, else the first player) and every participating player are submerged in water, using Minecraft's own `Entity.isSubmergedInWater` (eyes inside water). This is the predicate the port already used for Dive Ball environments; it is not inferred from an ocean biome. A player on a shore, in a boat or swimming at the surface is not submerged, so such battles use Water Surface from the biome rows. The underwater stage is the set of mapping rows with `"submerged": true` (the shipped row selects `rejuvenation:underwater` in every dimension).
3. **Configured structure.** If the wild Pokémon or a participating player stands inside a *piece* of a generated structure that a structure row names, that row's field is used. Structures without a row are ignored and resolution continues with the biome.
4. **Biome.** The ordered biome/tag/dimension/depth rows of `rejuvenation/mappings`, unchanged in behaviour (the Java tests compare the indexed lookup with the original first-match algorithm over 10,000+ situations).
5. **Fallback.** The catalog default, `rejuvenation:indoor`.

Wild battles use steps 2–5 when no selection exists. Trainer and PvP battles without a configured field stay opt-in and start without a field, as before; the Kanto league trainers keep their assigned fields.

The resolution source is recorded per battle (`FieldApi.origin`: `explicit`, `trainer`, `arena`, `underwater`, `structure`, `biome` or `fallback`) and logged with the battle-start timings.

## Structure mappings

Data-driven, analogous to the biome map: `data/<namespace>/rejuvenation/structures/<name>.json`.

```json
{"schemaVersion": 1, "rules": [
  {"structure": "minecraft:mansion", "field": "rejuvenation:back_alley", "reason": "Woodland Mansion"},
  {"tag": "minecraft:village", "field": "rejuvenation:city", "reason": "Village"}
]}
```

Each row names exactly one structure registry ID (`structure`) or one structure tag (`tag`), plus `field` and an optional `reason`. Rows are checked in order; the first row matching a structure the battle is inside wins. Malformed rows (both or neither key, bad identifiers, unknown fields, extra keys) are rejected by all three validators (Java reload, simulator, `validate.py`).

Shipped rows (`datapack/data/rejuvenation/rejuvenation/structures/vanilla.json`, generated by `generate.py`):

| Structure or tag | Field |
|---|---|
| `minecraft:mansion` | Back Alley |
| `#repurposed_structures:collections/mansions` | Back Alley (Repurposed Structures' mansion variants) |
| `minecraft:village_plains`, `_desert`, `_savanna`, `_snowy`, `_taiga` | City |
| `#minecraft:village` | City (vanilla villages plus every variant that joins the tag; Repurposed Structures adds its 14 villages to it) |

No other structure is mapped.

### Detection

At battle pre-start on the server thread, for the anchor position and each player position:

1. `StructureAccessor.getStructureReferences(pos)` lists the structures referenced by that chunk (data already stored in the chunk);
2. each referenced structure is looked up in a per-server, per-catalog-revision identity map of *mapped* structures, built once from the structure registry (IDs and tag membership resolved at that time);
3. only for a mapped structure, `getStructureContaining(pos, structure).hasChildren()` confirms the position is inside one of its pieces.

No registry enumeration, tag resolution or JSON work happens per battle, and unmapped structures are never inspected. A village's streets and buildings are pieces, so standing in the village counts; open fields between a village's pieces do not.

## Biome mapping changes (2026-10-05)

| Biome | Before | After |
|---|---|---|
| `minecraft:plains` | Grassy Terrain | Grassy Terrain (unchanged) |
| `minecraft:sunflower_plains` | Flower Garden (matched the generator's `flower` pattern) | **Grassy Terrain** |
| `minecraft:mushroom_fields` | Corrosive Field | **Fairy Tale Field** (and Cave when ≥12 blocks under its surface with no sky, like other surface biomes) |
| future biome IDs containing `mushroom` | Corrosive Field | **Fairy Tale Field** |

`minecraft:snowy_plains` stays Icy Field (a snow biome). `terralith:cave/fungal_caves` stays Corrosive Field: it is a cave, not a mushroom-field equivalent, and the Terralith pack is disabled in this world. Terralith's alpha islands are already replaced by `minecraft:mushroom_fields` through this profile's biome replacer, so they also become Fairy Tale Field.

## Indexing and reload

`RejuvenationFields.reload` builds the catalog, validates it and compiles `EnvironmentResolver.Index` (underwater rows, structure rows, biome rows with per-biome candidate lists) once per datapack revision. A reload replaces the whole catalog atomically; the structure identity map is rebuilt lazily for the new revision and registry. Battle start therefore reads entity/world state, looks up the cached index and selects the field.
